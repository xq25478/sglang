1.6 Markov head 与 Confidence head

DSparkV4MarkovHead(deepseek_v4_dspark.py:287-414)是 bigram bias head:markov_w1(VocabParallelEmbedding,vocab→markov_rank)把上一个 token embed 成 rank-markov_rank 隐向量;markov_w2(Linear markov_rank→vocab)投回 vocab 级 bias 加到 base logits。"rank"= Markov 近似的隐瓶颈维。采样是 semi-AR 的 run_markov_block(dspark.py:32-62):每步把上一步采样的 token 喂下一步 bias。

python/sglang/srt/models/dspark.py:32-62 run_markov_block
for step_idx in range(proposal_len):
    step_logits = head.apply_step_logits(base_logits[:, step_idx, :], token_ids=prev_tokens, ...)
    next_tokens = sampler(step_logits, step_idx)
    sampled_tokens.append(next_tokens)
    prev_tokens = next_tokens

DSparkConfidenceHead(dspark.py:287-328)是单层 Linear(hidden_size + markov_rank → 1),apply_sts 做 sigmoid(confidence_raw / sts_temperatures) 把原始 logit 映射到 [0,1] 生存概率。

compute_base_logits 的 x_post_hc tap

deepseek_v4_dspark.py:719-739 返回 (logits, x_post_hc),其中 x_post_hc 是 hc_head 之后、最终 norm 之前的 hidden —— 这个"抽头"直接喂给 compute_confidence,避免重算 hc_head+norm。它经 DraftProposal.confidence_tap 流到 planner。

def project_target_hidden(self, main_hidden):
    stage0 = self.stages[0]
    projected, _ = stage0.main_proj(main_hidden)        # hidden*N → hidden
    return stage0.main_norm(projected)

def write_target_hidden_kv(self, *, main_hidden, swa_loc, positions, pool):
    main_x = self.project_target_hidden(main_hidden)
    kvs = CommitKvProj.execute(main_x=main_x,
                               wkv_linears=[s.self_attn.wkv for s in self.stages])
    for stage, kv in zip(self.stages, kvs):

        pool.set_swa_key_buffer_radix_fused_norm_rope(layer_id=attn.layer_id, swa_loc=swa_loc,

2第二模块 · DSpark 详细原理

DSpark 是 confidence-scheduled 的自草稿推测解码:draft 与 target 共享 embed/lm_head,draft 不做独立完整前向,而是用 target 中间层 hidden 自举自己的 KV,再用 Markov 头逐 token 采样出 γ 个 draft;confidence head 对每个 draft 位置打生存概率;一个 host 侧优化把"总 verify token 预算"算成吞吐最优;Triton top-k kernel 把预算分到各请求 verify_len;compact 模式把幸存 token 压实成变长张量让 target 只 verify 有希望的 draft。核心链路在 dspark_worker_v2.py 的 _forward_decode。

2.3 Confidence-scheduled verify budget(核心创新)

三段:算 confidence(生存)→ host 优化算总预算 → Triton top-k 分配到 per-req verify_len。

(a) compute_confidence — 生存概率

dspark_planner.py:918。DSparkConfidenceHead 输出 per-(req,position) 标量 logit,apply_sts(dspark.py:326)做 sigmoid(confidence_raw / sts_temperatures),得到 [0,1] 生存概率 P(draft token i 被 target 接受 | 历史)。

(b) compute_verify_token_budget — 优化

dspark_planner.py:971-1008。给定 history_survival_probs [N, max_len](经 lag/refresh):

python/sglang/srt/speculative/dspark_components/dspark_planner.py:971-1008 (核心)
candidates = history_survival_probs[:, :max_len].flatten()
candidates = candidates[candidates >= survival_eps].to(float64)
candidates_sorted = torch.sort(candidates, descending=True).values
prefix_sum = torch.cumsum(candidates_sorted, dim=0)
# tau_star[k] = N + 最大的 k 个生存概率之和
tau_star = num_requests + torch.cat([torch.zeros(1), prefix_sum])
# 最大化吞吐比 theta = 期望接受 token 数 / step_time
# 加性模型: step_time[k] = bias + alpha(N) + theta(N+k)
#   → theta_ratio[k] = tau_star[k] / step_time[k]; idx = argmax
# 简单 SPS 表: sps[k] = lookup(N+k)
#   → theta_ratio[k] = tau_star[k] * sps[k]; idx = argmax
budget = idx   # 总 extra verify token 数(在 per-req floor 之上)

tau_star[k] = 若验证生存概率最高的 k 个 (req,position) 槽位的期望接受数:N(每请求一个 bonus)+ top-k 生存概率之和。argmax 选吞吐最优预算。

(c) HostConfidenceBudgetPlanner — relay lag

3第三模块 · PD 分离视角:DSV4-Flash + DSpark

PD(prefill-decode)分离把一个逻辑服务拆成 prefill 和 decode 两个独立进程(各自是完整的 Scheduler+engine)。本模块详解在此模式下 DSV4-Flash + DSpark 的计算模型、通信模型、KV Cache 模型,核心是 draft KV 如何在 decode 端 bootstrap。

3.1 PD 拓扑与协调

3.2 核心问题与 DSPark 解法

核心矛盾 DSpark draft 在 decode worker 上跑,但 decode worker 从不跑 target prefill forward,所以 target 中间层 hidden —— 那个种子 draft KV 的东西 —— 在 decode 端根本不存在。非 PD 时 draft 可复用同一 forward 里 target 刚算出的 hidden;PD 下这条路断了。

DSPark 三段解:

  1. Prefill 端捕获:_prepare_dspark_hidden_capture_for_batch(prefill.py:1298-1332)设 batch.capture_hidden_mode = CaptureHiddenMode.FULL + dspark_hidden_capture_layer_ids。DSV4 forward 在逐层 eager 循环里(deepseek_v4.py:2507-2557,捕获时显式禁用 TBO L2519,因为 TBO 无法暴露逐层 completed hidden)对每个 target layer append completed.mean(dim=1),末尾拼接成 logits_output.hidden_states。
  2. 跨进程传输:process_batch_result_disagg_prefill → _write_dspark_hidden_rows_for_batch(prefill.py:1421-1542)把捕获张量切片到 [hidden_start, hidden_start+hidden_len) 写进发送侧 DSparkHiddenRowPool,sender 作为 StateType.DSPARK_HIDDEN 发出。
  3. Decode 端注入:首步 _forward_decode → _maybe_inject_pd_prefill_tail(dspark_worker_v2.py:488-527)按 valid length flatten tail-hidden,算 positions,从 req_to_token 解析 cache_loc,调 TargetHiddenKvInjector.inject_target_hidden 写 draft SWA KV。

3.8 计算模型小结(PD 视角)

Prefill 端计算

  • target prefill forward(eager 逐层,禁用 TBO)以暴露逐层 completed hidden
  • 在 target layer ids 捕获 completed.mean(dim=1) 并拼接
  • 切片到 SWA 窗口后缀写发送池
  • 录 source_event 让 RDMA 等计算 stream

Decode 端计算

  • 跳过 prefill forward(PrebuiltExtendBatch 仅元数据)
  • 首步 _maybe_inject_pd_prefill_tail 注入 draft SWA KV
  • 之后每步走第二模块的完整 DSpark decode-step(draft propose → budget → verify → commit)
  • compact + graph folding + confidence relay 全程适用
